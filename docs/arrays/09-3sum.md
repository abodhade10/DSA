# 3Sum

## Problem

Given an integer array `nums`, find all unique triplets `[nums[i], nums[j], nums[k]]` such that:

- The three indices are different.
- The sum of the three numbers is `0`.
- Duplicate triplets are not allowed.

**Example**

Input: `[-1, 0, 1, 2, -1, -4]`

Output: `[[-1, -1, 2], [-1, 0, 1]]`

## Pattern

**Brute Force → Three Nested Loops**

**Optimized → Sorting + Two Pointers**

## Memory Trick

`SORT → FIX ONE → TWO POINTERS → SKIP DUPLICATES`

Remember: Fix one number, then find two numbers that add up to its negative.

For example, if the fixed number is `-1`, the other two numbers must add up to `1`.

---

## Approach 1: Brute Force

### Idea

Check every possible combination of three numbers using three nested loops.

For each combination:

1. Select the first number.
2. Select the second number after the first.
3. Select the third number after the second.
4. Check whether their sum equals zero.
5. If the sum is zero, sort the triplet and store it in a set to avoid duplicates.

### Dry Run

Input: `[-1, 0, 1, 2, -1, -4]`

Some combinations:

| Triplet       | Sum | Result            |
|---------------|----:|-------------------|
| `[-1, 0, 1]`  |   0 | Add               |
| `[-1, 0, 2]`  |   1 | Ignore            |
| `[-1, 2, -1]` |   0 | Add after sorting |
| `[0, 1, 2]`   |   3 | Ignore            |

The set ensures the same triplet is stored only once.

### Complexity

- **Time:** O (n³), excluding result-handling overhead.
- **Space:** Depends on the number of unique triplets stored; up to O (n²) for the output in general.

### Drawback

Checking every possible triplet is slow for large arrays because there are three nested loops.

---

## Approach 2: Optimized

### Idea

Sort the array first. Fix one number and use two pointers to find the other two numbers.

Sorted array:

`[-4, -1, -1, 0, 1, 2]`

### Steps

1. Sort the array.
2. Fix one number using the outer loop.
3. Set `left = i + 1`.
4. Set `right = last index`.
5. Calculate the sum of the three numbers.
6. If the sum is zero, save the triplet and move both pointers.
7. If the sum is negative, move `left` to the right to increase the sum.
8. If the sum is positive, move `right` to the left to decrease the sum.
9. Skip duplicate values to avoid repeated triplets.

### Dry Run

Input after sorting: `[-4, -1, -1, 0, 1, 2]`

**Step 1: Fix `-4`**

Try pairs using the left and right pointers.

- `-4 + (-1) + 2 = -3`
- `-4 + (-1) + 2 = -3`
- `-4 + 0 + 2 = -2`
- `-4 + 1 + 2 = -1`

The sum remains negative, so no triplet is found for `-4`.

**Step 2: Fix the first `-1`**

- `-1 + (-1) + 2 = 0`

Save `[-1, -1, 2]`.

Move both pointers:

- `-1 + 0 + 1 = 0`

Save `[-1, 0, 1]`.

**Step 3: Skip the duplicate `-1`**

The next fixed number is the same as the previous one, so skip it.

Final output:

`[[-1, -1, 2], [-1, 0, 1]]`

### Why Does It Work?

Because the array is sorted:

- Moving `left` right increases or maintains the value being considered.
- Moving `right` left decreases or maintains the value being considered.
- This lets us search efficiently without checking every possible pair.
- Skipping repeated values prevents duplicate triplets.

### Complexity

- **Time:** O (n²) — one outer loop and a two-pointer scan.
- **Auxiliary space:** O (1), excluding output and the sorting implementation.
- **Output space:** Depends on the number of unique triplets.

## Comparison

| Feature            | Brute Force               | Optimized                       |
|--------------------|---------------------------|---------------------------------|
| Technique          | Three nested loops        | Sorting + two pointers          |
| Time               | O(n³)                     | O(n²)                           |
| Duplicate handling | Set of sorted triplets    | Skip repeated values            |
| Performance        | Slow for large inputs     | More efficient                  |
| Best use           | Understanding the problem | Interviews and coding platforms |

## Interview Explanation

“I would first consider brute force with three nested loops, checking every possible triplet. That takes O (n³) time.

To optimize it, I sort the array and fix one number. Then I use two pointers to find the remaining two numbers. If the
sum is too small, I move the left pointer; if it is too large, I move the right pointer. I also skip duplicate values to
ensure unique triplets.

The optimized solution takes O (n²) time.”

## Common Mistakes

- Forgetting to sort the array before using two pointers.
- Not skipping duplicate fixed numbers.
- Not skipping duplicate pointer values after finding a triplet.
- Using `left <= right` instead of `left < right`.
- Moving the wrong pointer when the sum is too small or too large.

## Recall

Before an interview, remember:

1. Brute force: Three nested loops.
2. Optimized: Sort the array.
3. Fix one number.
4. Use two pointers.
5. Sum zero → save the triplet and move both.
6. Negative sum → move left.
7. Positive sum → move right.
8. Skip duplicates.

**One-line memory trick:**

`SORT → FIX ONE → TWO POINTERS → SKIP DUPLICATES`
